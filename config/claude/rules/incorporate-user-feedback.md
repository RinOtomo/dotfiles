# Incorporate User Feedback

ユーザーがレビュー・指摘した事項を記憶し、以後の作業に反映する。

## 基本原則

**ユーザーからの指摘は、同じミスを繰り返さないための規約として扱う。**

AIは会話をまたいで学習しないため、同じ指摘が繰り返されやすい。このルールは指摘内容をルールとして明文化し、恒久的に適用されるよう強制する。

## ワークフロー

### フェーズ1: 指摘の受け取り

ユーザーから指摘・修正依頼を受けたとき：

1. その指摘が「将来も適用すべき一般的なルール」か「今回限りの指示」かを判断する
2. 「恒久的に適用すべき」と判断したら、自動記録するか確認する（以下参照）

### フェーズ2: 記録の判定

#### 明示的に記録指示を受けた場合

ユーザーが「これはフィードバック記録して」「覚えておいて」と指示 → **必ず記録**

#### 自動判定する場合

以下のいずれかに該当する場合は、自動で記録対象と判定：

| 状況 | 判定 | 例 |
|-----|------|-----|
| **同じ指摘の2回目** | 記録 | 前回「テストは Arrange/Act/Assert を入れて」→ 今回も同じ指摘 |
| **修正後にユーザーが確認** | 記録 | 修正後「はい、このパターン今後守るべきですね」 |
| **プロジェクト固有ルール** | 確認 | 「このリポジトリではFactory使うが、他では直接生成」 |

迷った場合は：
- ユーザーに確認して記録するか判断する
- 「この指摘は将来の全作業に適用すべきルールですか？」と問い合わせる

### フェーズ3: 自動記録の実行

判定後、スキル `/record-feedback` を実行する：

```
スキル: record-feedback
目的: ユーザーからの指摘を ~/.claude/docs/feedback/ に自動記録し、overview.md を更新するため
```

スキルは以下を自動実行：
- カテゴリの判定（または確認）
- 日付と見出しの生成
- feedback ファイルへの追記
- overview.md の更新

## ルール

### MUST（必須）

- ユーザーから指摘・修正依頼を受けたとき、その内容が今後も適用すべきパターンかを判断する
- 恒久的に適用すべき指摘と判断した場合、スキル `/record-feedback` を実行して記録する
- 既存カテゴリに当てはまらない指摘の場合、新しいカテゴリを提案してからスキルを実行する
- 記録後、当該指摘を **この会話以降の全作業に適用する**

### MUST NOT（禁止）

- 指摘されたことを一度反映しただけで終わりにする（ルール化しない限り）
- 同じ指摘を2回以上受ける（2回目で必ず記録する）
- フィードバック記録を省略する（迷ったらユーザーに確認する）
- スキルなしに手動で feedback ファイルを編集する（スキルで統一し、overview.md 更新漏れを防ぐ）

## 記録対象・非対象の判定基準

### ✅ 記録する指摘

- **作業スタイル・プロセス**: 「テストファイルは tests/ に配置」「テストは Arrange/Act/Assert セクション分け」
- **ツール選択**: 「Bash ではなく Serena を使う」「Read ツールを優先」
- **出力形式**: 「結論を先に」「変更ファイルパスを明記」
- **コード記述**: 「不変性を優先」「3値以上の条件分岐は関数化」
- **判断基準**: 「迷ったときはユーザーに確認」など意思決定ルール

### ❌ 記録しない指摘

- **一度限りの指示**: 「このバグを修正してほしい」「ここの import を削除」
- **プロジェクト設定**: モデル名、API キー、ファイルパス等の具体的な値（メモリで管理）
- **技術仕様**: 既に `CLAUDE.md` や `docs/` に記載されている内容
- **既存の feedback 重複**: `overview.md` に既に記録されている指摘と同一内容

## カテゴリ分類の指針

| カテゴリ名        | 対象となる指摘                       |
| ----------------- | ------------------------------------ |
| `output-format`   | 出力形式・文体・応答スタイルへの指摘 |
| `code-style`      | コードの書き方・命名・構造への指摘   |
| `tool-usage`      | ツール選択・呼び出し方への指摘       |
| `workflow`        | 作業手順・進め方への指摘             |
| `rule-management` | ルールファイル自体の管理方法への指摘 |

上記に当てはまらない場合は内容を表す英小文字のカテゴリ名を新設する。

## フィードバック追記フォーマット

カテゴリファイル (`<category>.md`) への追記形式：

```markdown
### [YYYY-MM-DD] [短いタイトル]

**指摘内容**: ユーザーが指摘した問題の要約
**適用ルール**: 今後どのように振る舞うべきか（具体的・行動可能な形で）
```

## ファイル構成

```
~/.claude/docs/feedback/
├── overview.md          # 全カテゴリの索引・件数サマリ
├── output-format.md     # 出力形式への指摘
├── code-style.md        # コードスタイルへの指摘
├── tool-usage.md        # ツール使用への指摘
├── workflow.md          # 作業フローへの指摘
└── rule-management.md   # ルール管理への指摘
```
