# Claude Global Instructions (Japanese)

## Language

- 思考は英語で行い、回答は日本語を基本とする。
- コマンド、パス、設定キー、エラーメッセージは英語のまま示す。

## Feedback

- 作業を開始するときに `docs/feedback/overview.md` を読む
- overview.md の件数が 0 のカテゴリは読まない
- 件数が 1 以上のカテゴリは、依頼内容と関連するカテゴリのファイルのみ読む

## Work Style

- 既存挙動を壊さない最小差分を優先する。
- 提案だけで止めず、可能なら実装と検証まで進める。
- 変更点と影響範囲を短く明確に説明する。

## Output

- 結論を先に書く。
- 変更したファイルパスを明記する。
- 未実施の検証があれば理由を明示する。

### 原則

- DRY・KISS・YAGNI の原則に従ってください。
- 過度な広報互換性のケアなどはサイクロマティック複雑性を増やさずに実現できる場合を除き、後方互換性のためのシャムやフォールバックパスは不要。
- 既存の処理を踏襲することを前提に新規で関数やモジュールを CQS/CQRS 的な設計を検討してください
- 変数の再代入を避けること
- また if 文での条件判定などの際に 3 つ以上の値を基に判定結果を算出する場合は小さい関数を切る様にしてください
  - これは値の不変性を疑似的に再現するため
